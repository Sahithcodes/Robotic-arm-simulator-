# Pick-and-place diagnosis and geometry report

## Robot and coordinate frame

- The six-joint chain uses standard DH transforms in meters and radians. Approved dimensions remain `d1=0.70`, `l2=0.43`, `l3=0.37`, `d4=d5=0`, `d6=0.10 m`; limits remain J1 `[-170,170]`, J2 `[-225,45]`, J3 `[-216,90]`, J4 `[-110,170]`, J5 `[-100,100]`, J6 `[-266,266]` degrees. The DH table is in [robotConfig.ts](../src/robot/robotConfig.ts).
- World Z is up, the table is in XY, the DH base is `(0,0,0.28) m`, and the shoulder is at z=`0.98 m`. The visible pedestal rises from the floor and the column reaches the shoulder.
- The support and object-placement keep-out radius is unchanged at `0.20 m`. A book-center keep-out includes the book half-diagonal, so its effective center radius is `0.264 m`.

## TCP and grasp geometry

- FK returns flange `T06` and TCP. TCP is exactly `T06 * Tz(0.075 m)`, using the rendered finger length as the tool length. Fingers extend along local +Z; top-down points tool +Z toward world -Z.
- The book measures `0.100 × 0.080 × 0.025 m`. The max opening is `0.130 m`, the closed outer finger-center span is `0.092 m`, and each finger is `0.012 m` thick. The gripper width axis aligns with the book's narrower dimension. At full opening the inner-face gap is `0.118 m`, leaving `0.019 m` per side; closed inner faces meet the `0.080 m` book width.
- Finger boxes are transformed by the full FK rotation and translation for clearance checks. Attachment remains kinematic: the store saves the object offset in the flange frame and updates its world pose while held.

- Before resize: `0.34 × 0.20 m`, center `(0.71,-0.04) m`, top z=`0.78 m`. The x=`0.54 m` table edge was only `centerX - width/2`; it was not generated by a reach calculation. For comparison, the 2 cm top-down FK/IK grid reached horizontal radii `0.495–0.805 m`; x=`0.54 m` at y=0 is within that band and outside the base keep-out. On the enlarged candidate, a book centered at x=`0.54 m`, y=0 is table-valid but the complete planner rejects its **PRE-GRASP** pose as `collision with table`. That is a link/table path-safety result, not the keep-out radius or an IK limit. The 25 mm clearance plane is a simplified centerline test; the link boxes have up to 25 mm vertical half-thickness, so current evidence does not show that margin is over-conservative.

- The rectangular candidate is only 45.6–64.2% pickable among valid placements depending on yaw. It does not give a reliably mostly-pickable rectangular surface across all book orientations. A better matching shape to evaluate is an **annular-sector tabletop** centered on the base axis, roughly `0.60–0.78 m` in radius and focused on the positive-X side. This shape is proposed but not implemented pending the table-shape decision.

## Current pick implementation and checks

- The object position, dimensions, yaw, and reachability live in Zustand. Autonomous Pick reads the live object pose; the existing fixed P1–P4 predefined task remains separate.
- Numerical IK constrains position, tool-Z direction, and yaw independently, tries several seeds, respects joint limits, and reports residuals and limit hits. The planner uses a 30° tilted-grasp fallback after trying more vertical poses.
- The green overlay is generated from the same complete pick planner used by Autonomous Pick, on a one-centimeter grid. It is cached by yaw, robot pose, table, book, and DH configuration; yaw changes are debounced. Book dragging is locked during execution.
- Headless checks include 200 FK/IK round trips (worst measured position error `1.482 mm`), 20 completed pick sequences, full-FK finger clearance at open/close, and finger/table collision samples along the path. The exact 1 cm planner-grid test covers all four yaw values.

## Diagnosis of the original unreliable grasp

1. TCP geometry was not a single shared definition: the planner had a `-0.085 m` contact-offset hack while the rendered gripper extended along local +Z. Planner targets, grasp checks, and visual fingers therefore did not refer to the same point.
2. The old orientation acceptance compared the tool rotation to identity, which did not express “tool +Z points down”; it also did not separately align yaw with the book's narrow dimension.
3. The original tabletop was too large/far for the actual reachable region and its fixed edge at x=`0.54 m` was a chosen table bound, not a calculated workspace limit. Link/table collision checks could then reject otherwise reachable grasp targets along the descent or path.
4. The prior task used fixed object coordinates and did not reliably kinematically attach the object after a verified close. The current plan reads store state and follows the gripper after alignment verification.
